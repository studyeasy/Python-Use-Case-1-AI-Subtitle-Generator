Subly — Application Flow

How a user's media file becomes a downloadable SRT, end to end.

The simple version

Five steps. This is everything you need to hold in your head. 

flowchart LR
    A["👤 User
uploads a video"]
    B["☁️ Saved to S3"]
    C["⚙️ Background worker
runs Whisper"]
    D["📝 SRT saved
back to S3"]
    E["⬇️ User downloads
the SRT"]

    A --> B --> C --> D --> E

While the worker is busy, the page asks the server every 2 seconds "are we there yet?" and shows a progress bar.

1. Architecture (one box per piece)

Browser → API → (queue + worker) → S3. Database tracks progress. 

flowchart LR
    Browser["🌐 Browser
(Next.js)"]
    API["🚀 FastAPI"]
    Queue[("📮 Redis
queue")]
    Worker["⚙️ Celery worker
+ Whisper"]
    DB[("🗄️ SQLite
project status")]
    S3[("☁️ S3
files + SRTs")]

    Browser -- "upload / poll / download" --> API
    API -- "save file" --> S3
    API -- "save row" --> DB
    API -- "enqueue job" --> Queue
    Queue --> Worker
    Worker -- "fetch file" --> S3
    Worker -- "save SRT" --> S3
    Worker -- "update progress" --> DB
    API -- "read status" --> DB

2. Sequence — what happens in time order

After the upload, the browser polls and the worker transcribes — in parallel. 

sequenceDiagram
    actor User
    participant FE as Browser
    participant API as API
    participant W as Worker
    participant S3 as S3

    User->>FE: choose file, click Upload
    FE->>API: POST /projects (file)
    API->>S3: save file
    API->>W: queue job
    API-->>FE: project id

    loop every 2s
        FE->>API: status?
        API-->>FE: "still working… 47%"
    end

    W->>S3: fetch file
    W->>W: run Whisper, build SRT
    W->>S3: save SRT
    W->>API: mark COMPLETED

    FE->>API: status?
    API-->>FE: "done"
    User->>FE: click Download
    FE->>S3: GET SRT
    S3-->>User: file.srt

3. Project status machine

The status column on the projects table moves through these states. The UI's polling stops as soon as it lands in a terminal state. 

stateDiagram-v2
    [*] --> PENDING: row created
    PENDING --> QUEUED: task enqueued
    QUEUED --> TRANSCRIBING: worker picks up
    TRANSCRIBING --> TRANSCRIBING: progress 0→99
    TRANSCRIBING --> COMPLETED: SRT uploaded
    TRANSCRIBING --> FAILED: exception (S3, Whisper, ffmpeg…)
    QUEUED --> FAILED: task lost / worker crash
    COMPLETED --> [*]
    FAILED --> [*]

4. Where each piece of state lives

State Lives in Notes
User identity (JWT) AWS Cognito + browser localStorage Validated on every API call via get_current_user.
Project rows (status, progress, S3 keys) SQLite at /data/subly.db Shared docker volume between API and worker containers.
Uploaded source media S3 uploads/{project_id}/<filename> Deleted with the project row.
Generated SRT S3 subtitles/{project_id}/<stem>.srt Served to the browser via a 15-minute presigned GET URL.
Task queue + task results Redis (redis:6379/0 and /1) Celery broker + result backend.
Whisper model weights Docker volume subly-whisper-cache Downloaded once on first transcription (~470 MB for small).
